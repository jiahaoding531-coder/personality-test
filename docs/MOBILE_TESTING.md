# TravelMind 手机真机验收

本阶段不安装 PWA，也不修改后端接口。目标是用手机浏览器验证定位、推荐、反馈与移动端布局。

## 测试前准备

1. 启动 PostgreSQL 和 Spring Boot 后端，确认电脑访问 `http://localhost:8080` 正常。
2. 在 `frontend/` 目录启动允许局域网访问的开发服务器：

   ```text
   npm run dev -- --host 0.0.0.0 --port 5174
   ```

3. 手机和电脑连接同一个 Wi-Fi，在 Windows 中查询电脑的局域网 IPv4 地址。
4. 手机访问 `http://电脑局域网IP:5174`。如果 Windows 防火墙询问是否允许 Node.js，请只允许当前可信的专用网络。

局域网 HTTP 地址适合检查布局、手动坐标和推荐链路，但多数手机浏览器不会在非安全的 HTTP 页面开放 GPS。页面会明确解释原因，并提供测试位置与手动坐标。

## 真实 GPS 测试

浏览器定位要求 HTTPS（`localhost` 只对电脑本机例外）。请把当前前端放到可信的 HTTPS 地址，或为本地测试配置手机信任的 HTTPS 证书，再用手机打开该地址。

### Cloudflare Quick Tunnel（仅用于临时测试）

Quick Tunnel 不需要购买服务器或域名。它只把 Vite 的 `5174` 端口临时映射成一个随机的
`https://*.trycloudflare.com` 地址；后端仍只在本机 `8080` 运行，浏览器的 `/api` 请求继续
由 Vite proxy 转发，因此不会产生 HTTPS 页面请求 HTTP API 的混合内容。

依次打开三个 PowerShell 窗口：

```powershell
# 窗口 1：后端（必须在 backend 目录执行 Maven）
cd <项目目录>\backend
.\mvnw spring-boot:run

# 窗口 2：前端
cd <项目目录>\frontend
npm run dev -- --host 0.0.0.0 --port 5174

# 窗口 3：临时 HTTPS 隧道
$env:HTTPS_PROXY = 'http://127.0.0.1:7897'
$env:HTTP_PROXY = 'http://127.0.0.1:7897'
& 'C:\Program Files (x86)\cloudflared\cloudflared.exe' tunnel --edge-ip-version 4 --url http://localhost:5174 --no-autoupdate
```

上面的代理变量只对当前 PowerShell 窗口及其子进程生效，不会修改 Windows 全局代理。
这台电脑上 `cloudflared` 的安装目录暂未加入 `PATH`，所以命令使用完整路径；如果以后已经能直接执行
`cloudflared --version`，也可以把完整路径简写为 `cloudflared`。

`cloudflared` 输出的 `https://*.trycloudflare.com` 地址就是手机入口。地址每次启动都可能变化，
不要把它写进代码或配置。测试结束后，在窗口 3 按 `Ctrl+C` 关闭隧道；前后端也可分别按
`Ctrl+C` 停止。

安全提醒：隧道运行期间，知道随机地址的人可以访问测试页面及经 Vite 转发的 API。不要在
命令或公开日志中输出数据库口令、API key 或手机的真实 GPS 坐标，完成测试后及时关闭隧道。

手机端验证步骤：

1. 用手机打开临时 HTTPS 地址并登录。
2. 浏览器询问位置权限时选择“使用期间允许”或同等选项。
3. 确认“本次出行”的位置由“位置待确认”更新为地名；高德服务不可用时显示坐标也属于安全降级。
4. 输入“我累了，想找个安静的地方”，确认出现附近推荐，且不会突破已设置的最远距离。
5. 对地点提交反馈，再继续输入自然语言，确认推荐链路仍可用。
6. 不允许定位时，仍可在位置设置中使用杭州西湖、平顶山市中心或手动经纬度。

1. 登录已有旅行画像的账号，进入 TravelMind 对话页。
2. 打开「位置与限制」，点击「使用我的当前位置」。
3. 手机弹出权限提示后选择允许。
4. 确认「本次出行」显示服务端返回的地名；无法取得地名时，应显示本次 GPS 经纬度，不能显示虚构地点。
5. 输入「我累了，想找个安静的地方」，确认返回附近 Top 3。
6. 对一个地点点击「想去」或「不感兴趣」，再点击「换一批」，确认流程可继续。

自然语言输入依赖后端已经配置可用的 AI Key，或者在偏好设置中填写用户自己的 Key。没有 Key 时，可以继续用快捷需求检查确定性推荐链路。

## 没有定位权限时测试

打开「位置与限制」后，可以选择：

- 「杭州西湖测试位置」：立即使用 `30.2420, 120.1400` 发起推荐，并显示「杭州西湖」。
- 手动经纬度：填写纬度和经度，点击「应用位置与限制」。页面显示可核对的坐标并按该位置推荐。

测试拒绝定位、定位超时或 HTTP 局域网限制时，页面都应保留这两个替代入口，不应卡死或假装定位成功。

## 移动端验收尺寸

至少检查 360、375、390、412、430px 宽度：

- 页面没有横向滚动。
- 底部输入栏可见，输入框获得焦点后仍能发送。
- 推荐卡片、反馈按钮和「换一批」可以点击。
- 位置设置抽屉不会超出屏幕，并能独立滚动。
- 数字输入框不会因字号过小触发浏览器自动放大。
