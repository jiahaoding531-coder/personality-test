# TravelMind 离线公平曝光实验

本工具直接复用 RecommendationEngine，不加载 Spring、不连接数据库、不调用高德或模型，不改变线上推荐。全部 Java 代码在测试目录，不进入生产 jar。

附带输入是 **SYNTHETIC_TEST_ONLY 合成测试样例**，不对应真实地点、用户或客流。其结果只验证程序行为，不能证明现实文化节点的曝光、接受率或满意度改善。

## 运行

在 worktree 根目录打开 PowerShell：

```powershell
.\scripts\run-offline-fairness.ps1
```

默认读取 `backend/src/test/resources/experiments/synthetic-cultural-nodes-v1.json`，在 `backend/target/offline-fairness/` 下创建新结果目录。仅使用本机 Maven 缓存；缺依赖时停止，不自动联网。

指定输入与新输出目录：

```powershell
.\scripts\run-offline-fairness.ps1 -InputFile 'D:\实验输入\已核验输入.json' -OutputDirectory 'D:\实验输出\新的一次运行'
```

程序拒绝覆盖已有目录。完整输出必须包含：

- `input.json`：原始输入的逐字节副本；只使用公开或合成坐标，不放个人 GPS、用户资料或密钥。
- `report.json`：三组逐轮候选、原始五因子、排序优先级、入选 ID，以及分场景/总体指标。
- `manifest.json`：输入、报告、关键源码、实际运行字节码的 SHA-256，以及 Java 版本和数据声明。

输入校验失败不创建本次结果目录；磁盘故障可能留下部分文件，须保留现场，不使用不完整结果。报告没有运行时间戳，可逐字节比对。仅保存 Git HEAD 不足以标识未提交源码；应同时保留源码和清单，不要在编译与运行之间修改源码。

## 输入契约

以附带 JSON 为完整示例。字段必须显式给出，允许为空的字段写 `null`；缺少数字字段不按零处理。未知字段、重复 JSON 键、数字字符串及把小数传入整数字段均拒绝，不允许静默截断票价、画像、ID 或种子。

| 字段 | 说明 |
|---|---|
| datasetId、provenance | 数据版本及来源/许可声明 |
| datasetKind | SYNTHETIC_TEST_ONLY 或 USER_SUPPLIED；后者仅表示用户提供，不代表工具已核验 |
| coordinateSystem | SYNTHETIC、WGS84、GCJ02；节点及查询必须一致，工具不转换坐标 |
| longTailPlaceIds、longTailDefinition | 运行前冻结的集合和定义，不允许按测试结果选择 |
| seed | 查询顺序随机种子，样例为 20261026 |
| fairnessWeight | [0,1] 欠曝光奖励权重，样例 0.35 不是经真实数据调优的参数 |
| nodes | ID、名称、类别、坐标、七维人工属性、室内程度、质量、门票、时长、营业时段 |
| queries | 唯一 ID、场景 stratum、坐标、本地时刻、半径、时间、预算、完整八维有效画像、状态、临时偏向 |

禁止把来源不明的历史坐标直接标为 WGS84 或 GCJ02。工具仅校验声明一致，不能证明声明属实。每个 stratum 应对应可比较的地域和机会范围；输入制作者负责统一本地时刻语义，程序不做时区转换。天气固定为空，状态只读取显式值，反馈和 seen 冻结，不模拟用户点击或喜欢。

营业时段同时为空时沿用原引擎的全天开放规则，不代表实时营业已确认。跨午夜时段因原引擎不支持而拒绝。最多 1000 节点、1000 查询，二者乘积最多 50000，文件最多 5 MB。

## 策略及复现

候选先按 ID 排序；使用一个种子打乱查询序列一次，三组共用同一序列。原引擎返回每轮完整的可行评分集合，保留所有原有距离、时间、门票和静态营业过滤，每次最多取三项：

1. DISTANCE：直线距离升序，同分按 ID。
2. RELEVANCE：原五因子综合分降序，同分按 ID。
3. FAIR_EXPOSURE：`(1-lambda)*原分 + lambda/(1+已入选次数)` 降序，同分按原分、ID。

已入选次数只读取本策略、本场景之前完成的选择；每组、每场景从零开始。试排和其他组不更新它。原分仍保存在 baseScore，公平优先级另存 priority。距离组 priority 为负距离，仅统一比较方向，不是相关性分。

这是启发式对照，没有严格公平配额保证。lambda 为零时公平组应与相关性组一致。应在独立验证集调参，再冻结参数和测试集；不能只展示有利种子。

## 指标与解释边界

measurement 为 SIMULATED_SELECTIONS_EQUAL_POSITION_WEIGHT：入选一个位置计一次，前三位置等权。**没有采集浏览器真实曝光，不代表观看、导航或到访。**

- selections：入选次数，保留可行但零入选节点。
- opportunities：通过同轮全部硬过滤的次数；从未可行节点不进入公平分母。
- Gini：`sum_i sum_j abs(E_i-E_j)/(2*n*sum_i E_i)`；无入选时为 null。
- 机会归一化 Gini：先取 `E_i/opportunities_i` 再算 Gini，仅是机会不均的辅助诊断。
- 长尾份额：预声明集合入选次数/总入选次数；零总量为 null。样例的 4、5、6 只是测试分组，不代表现实冷门。
- 覆盖率、零曝光份额：在有可行机会的节点内计算；无可行节点为 null。
- meanBaseScore：所选原综合分均值，仅是内部相关性代理。
- relevanceRetention：实际选择原分总和/同轮原相关性前三原分总和；分母为零时 null。
- meanDistanceKm：已选地点平均直线距离；无选择时 null。
- emptyQueries：无候选查询数。

报告含各场景及总体汇总。总体 Gini 会受地理机会和场景比例影响，不能单独解释成算法不公平。没有独立人工相关性标注，因此不生成 nDCG；没有用户实验，因此不生成接受率、满意度或统计显著性结论。
