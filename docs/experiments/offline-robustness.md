# TravelMind 多种子与权重敏感性实验

本轮把单次公平曝光实验扩展为可复现的组合实验。只使用原有离线数据契约和原推荐引擎，不修改线上推荐、餐饮、画像或行为事件。所有 Java 实现位于测试源码，不进入生产 jar。

这一步回答：**同一组输入，仅改变请求先后和均衡权重，结果会变化多少？** 它不证明真实文化节点的公平收益，也不替代真实数据采集、用户研究或独立测试集。

## 一键运行

在当前 worktree 根目录的 PowerShell 执行：

```powershell
cd <项目目录>
.\scripts\run-offline-robustness.ps1
```

默认使用六个合成节点、十八个合成查询，以及 `synthetic-robustness-plan-v1.json` 中的十个种子、五个权重：0、0.15、0.35、0.6、1。共 50 个组合，每个组合都完整执行距离优先、相关性优先和曝光均衡三组。

计划在运行前保存，完整公布全部组合。不从结果中删掉不利种子，不自动选出“最佳参数”。0 权重是对照，1 权重用于观察极端取舍，不代表建议线上采用。

可选参数为 `-InputFile`、`-PlanFile`、`-OutputDirectory`，都接受完整本地路径。计划的数据集编号必须与输入一致。叶县的证据登记 JSON 不是实验输入，目前仍不允许拿未核验的坐标或未知属性直接做真实节点实验。

默认在 `backend/target/offline-robustness/` 创建全新的运行目录，包含：

- `input.json`：原输入的逐字节副本；不能放个人 GPS、用户身份或密钥。
- `plan.json`：原实验计划的逐字节副本。
- `report.json`：全部组合的完整逐轮报告、各场景与总体摘要、配对差值。
- `summary.md`：可读的全部权重/策略/场景对照表。
- `manifest.json`：上述四个文件、源码、运行字节码、入口脚本的 SHA-256 和 Java 版本。

重复运行到相同目录会拒绝，不覆盖旧实验。输入或来源校验失败不创建结果目录；若写文件时发生磁盘故障，可能留下不完整目录，须保留现场，不使用未完成清单的报告。输出属于本机生成文件；长期保存实验时应连同对应源码快照保存，单独保存 Git HEAD 不能代表未提交代码。

## 比较规则

1. 每个组合仅替换输入里的 seed 和 fairnessWeight，其他数据、条件、画像、状态不变。
2. 每次执行独立计数；同一组合内三组共享查询顺序和硬过滤。不同组合、策略和场景不借用彼此的历史选择。
3. 汇总分别保留总体与各 stratum，不把不同地区的机会差异藏进一个均值。
4. 每个指标保存有效数、缺失数、均值、最小和最大；无结果或零分母仍是 null，不算成零。
5. 同种子、同权重、同场景计算“公平组 − 相关性组”。Gini 负值表示更均衡；长尾份额或原分保留率负值表示下降。
6. 种子只改变同一批查询的顺序，不是独立采样的用户；最小/最大是敏感性范围，不是置信区间，没有统计显著性结论。

仅统计模拟入选，前三位置等权。这里的原分保留率是现有推荐评分的内部代理，不是用户满意度；“长尾”仍是样例预指定测试组，不能冒充真实人气排名。

## 输入和内存保护

- 2–20 个不重复种子，1–6 个不重复权重；必须含 0，范围 [0,1]；最多 60 个组合。
- 所有组合累计查询最多 10000 轮；累计节点×查询最多 250000，空集合也至少按 1 计。
- 计划编号、数据集编号、查询 ID、场景名最多 128 字符，避免反复展开巨大文本。
- 输入最多 5 MB、计划最多 64 KB；拒绝未知/重复键、尾随 JSON、数字字符串及小数种子。
- 顺序运行，Java 堆限制 512 MB；报告流式写入并同步计算哈希。没有在最大允许规模下做内存压测，因此上限仍是工程保护值，不是性能承诺。
