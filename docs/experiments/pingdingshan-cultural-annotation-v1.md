# 平顶山文化节点采集与标注规程 v1

日期：2026-10-27。用于离线实验准备，不用于改写线上 places。

## 1. 先确定“一个节点”是什么

第一版以公众可访问的场所整体为单位。场所、内部建筑、展厅与机构名称不混在同一候选池中。同址不同名称保留别名与证据；不确定是否同址时暂不合并，也不让两个疑似重复实体同时进入实验。

市域证据池需要先按实际地理范围确定实验片区。一个场景只有三个可行节点而每轮选三个时，几乎不存在重排空间；应如实报告这个事实。不能靠扩大硬距离约束或把内部建筑拆分来制造差异。

## 2. 每个节点必须补齐的证据

| 项目 | 应记录内容 | 未确认时 |
|---|---|---|
| 实体身份 | 规范名、别名、官方资料 URL、页面日期、核验日期、场所层级 | 不合并或拆分猜测的实体 |
| 当前可达性 | 公众是否能合法进入、入口位置、现场或机构最新说明及日期 | 不当成可立即游览的推荐对象 |
| 坐标 | 经纬度原精度、明确坐标系、提供者与对象 ID/版本、来源 URL 或自采记录编号 | 不转换，不进入距离实验 |
| 点位语义 | 公共入口、测量点、建筑点、范围中心分别说明 | 中心点不得冒充入口或导航终点 |
| 精度 | 来源给出的精度，或自采设备 accuracy；独立核对结果 | 小数位数不等于测量精度 |
| 使用条件 | 许可证/授权依据、署名要求、是否可公开分发 | 不把来源公开等同于再利用授权 |
| 属性 | 原始证据、打分规则版本、标注者和复核者 ID | 不自动从名称或 LLM 生成数值 |
| 费用与时间 | 票价适用日期/人群、游览时长标注依据、开放日期和时段 | 不把未知价格填0，不把未知开放时间填全天 |
| 人气/曝光依据 | 独立统计口径、观测窗口、分母、来源与许可 | 不称“真实长尾” |

自采坐标只记录经同意采集的公共场所入口，不记录个人住宅或移动轨迹。浏览器 Geolocation 按已有契约标为 WGS84，保留 accuracy 和采集时间；“浏览器接口声明 WGS84”仍需同实体入口核对，不等同测绘精度保证。不得展示采集人的精确私人位置或身份。

开放地图对象记录需保留类型与 ID、版本/时间及坐标语义。面状对象的范围中心不天然位于可通行入口。高德 GCJ02 与 WGS84 不混算；已有历史 places 坐标不作为校准基准。

## 3. 属性标注保持与原引擎含义一致

现有 `PlaceTraits` 为 nature、culture、food、photography、hiddenGems、lively、walking，另有 indoor、quality 等字段。画像包含八维，但 **PLANNING 不参与当前地点评分**，不得把它宣称为本次重排的有效信号。

第一轮可预先约定 0/25/50/75/100 五档人工量表，但在少量独立校准节点上写清每档证据后才使用：

- 自然、人文、美食、摄影：描述可核实的体验构成；不是官方评级，不把名称直接映射为100。
- 步行强度：依据场所范围、台阶及实地路线记录；到景点的直线距离不是场所内部步行强度。
- 室内程度：依据可访问的室内/室外活动区域；不由天气或当前客流猜测。
- lively：如确需使用，只能作为有规则的静态环境标注或注明窗口的实测；不表示实时拥挤。
- hiddenGems：当前只有人工“小众”含义，不能充当公平实验的独立长尾真值。缺证时不硬填分。
- quality：需要单独定义评分含义和标注规则，不从文物级别或景区星级直接推算0–100分，也不把它伪称用户满意度。

至少两名标注者独立打分，记录分歧与复核结论。标注者不看公平实验结果后调分。缺乏证据的字段保持 null；暂不导出为引擎要求的非空整数。

若为了机制分析冻结某些因子为统一常数，必须另建明确标注“真实地点+人工控制条件”的场景，由实验设计预先决定；不能覆盖事实字段或据此报告真实推荐质量。本轮不创建这类输入。

## 4. 原引擎暂不支持的事实不能悄悄简化

- 当前实验输入的票价、游览时长、画像及地点属性必须有值。证据不齐时，清单可保存 null，但不能直接导出为运行输入。
- 原引擎的开放时段只有一对时间；周一闭馆、节假日、分时开放、预约等无法完整表达。不能把空时段当全天开放。应在有最新资料的固定场景中预先确定可访问候选，或明确将时间开放因素冻结为人工模拟条件。
- 建议游览时长是人工估计，不能解释成真实完成时长或交通耗时。
- 不改引擎距离、票价和时间硬约束，不用坐标转换试错，未知实时信息不补造。

## 5. 实验前冻结单

| 冻结项目 | 要求 |
|---|---|
| 节点池 | 去重、场所层级一致、证据完成；保留被排除项和原因，不能只留对公平算法有利的节点 |
| 画像 | 人工场景或经同意取得的问卷分开标注；不混入私人账户、后续反馈 |
| 查询 | 同一中心/坐标系/时刻/半径/时长/预算序列供三组共用；不能按算法改条件 |
| 长尾组 | 独立人气资料定义，或明确称“冻结相关性基线中的低入选组”；不能用实验后的结果反选 |
| 参数 | 公平权重、种子列表和版本在观察比较结果前固定；调参集与评估集分开 |
| 状态 | 每策略、每场景从零开始；不复用其他组的曝光计数；无实时天气、无自动反馈更新 |
| 相关性 | 原评分保留率只是内部代理；若声称用户更满意，需另做盲评或真实用户研究 |
| 统计 | 逐场景和总体同时报告；包括不利结果、空结果及可行机会不均，不只报告最优种子 |

多种子改变的是同一人工查询序列的先后，并不产生新的独立真实用户样本。不要用它伪造样本量或显著性。

## 6. 数据进入实验的门槛

必须同时满足：实体与入口核验、坐标系一致、使用条件明确、关键属性与硬条件有据、节点层级去重、查询与目标组定义冻结。

当前证据清单全为 `experimentEligible=false`，这是有意的保护标记。既有 Java 运行器只校验输入合法性，不会替人确认真实性、许可或访客可达性；正式生成输入仍需人工复核记录。

没有独立人气依据时，最多评价模拟入选的均衡性，不能将其改名为真实曝光提升。BehaviorEvent 现有动作记录也不是可见曝光；不能拿导航点击当作到访。
